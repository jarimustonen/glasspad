## Rationale
- **maturity: mvp** — raised from the inferred `spike` by the maintainer: the goal is a real
  public crates.io release, and mvp is the honest target (the codebase is substantial — v0.2
  host rewrite, security suite, issue tracker). CI is added in the same sequence, so the `ci`
  badge/producer floor is satisfied.
- **ecosystems: [rust]** — the sole manifest is `Cargo.toml`, defining one published
  `glasspad` package with a library crate root and the installed CLI binary. Not
  `[rust, binary]`: `binary` is only for repositories with no package ecosystem.
- **targets: three CI-delegated release legs** — `.github/workflows/publish-crates.yml`
  publishes the single `glasspad` package to crates.io on a version-tag push, so that target
  uses `cargo-publish-ci`: the release host must never run a local `cargo publish`. The same
  tag triggers cargo-dist's generated `.github/workflows/release.yml`, which creates the
  GitHub Release with prebuilt binaries and publishes the Homebrew formula to
  `jarimustonen/homebrew-glasspad`. Homebrew is a required install channel
  (`brew install jarimustonen/glasspad/glasspad`). Both cargo-dist-owned channels are explicit
  targets, so Shipshape can observe the complete surface without becoming a second tap
  writer. Do not change the Homebrew adapter to `homebrew-tap`: cargo-dist is the formula's
  sole writer, while that adapter would make Shipshape compete for the same tap.
- **distribution** — cargo-dist emits shell + Homebrew installers and prebuilt binaries for
  Apple Silicon macOS plus GNU Linux on arm64 and x86_64. Linux intentionally uses `gnu`, not
  `musl`; Intel-mac and Windows have no prebuilt artifact and remain supported through
  `cargo install glasspad`. The personal self-hosted Apple Silicon runner routing remains an
  infrastructure detail in `dist-workspace.toml`, not a portable contract default.
- **versioning: semver** — the project uses `vMAJOR.MINOR.PATCH` tags and remains pre-1.0,
  with no declared major cap.
- **changelog.mode: curated** — single contributor in `git shortlog`, so no fragment
  merge-conflict pressure; **source: issuectl-trailers** because `issues/` (issuectl) is the
  tracker of record.
- **conventional_commits: false** — default (cutter asks for the bump). Your recent commits
  *do* follow conventional format (`feat(cli):`, `fix(cli):`), so flipping this to `true`
  would let `/shipshape-release` derive the bump automatically — a low-risk maintainer choice.
- **release.model: gated** — the version/tag cut is a discrete checks-gated transaction
  rather than an automatic publish on every merge. Under the repository's standing release
  autonomy, the release operator proceeds without a separate permission prompt once every
  mandatory gate passes.
- **provenance_level: keyless** — the cargo-dist binary path emits GitHub build-provenance
  attestations via OIDC. crates.io publication remains token-authenticated, so this records
  the binary channel's verifiable provenance rather than claiming crates.io trusted
  publishing.
- **dependency_bot: dependabot** — mvp default; `/shipshape-ci` emits `.github/dependabot.yml`.
- **health_badges: [ci, registry, license]** — `ci` producer is `ci.yml`; `registry` is the
  crates.io version badge (crate published as of 0.2.0); `license` is MIT.
- **license: MIT** — chosen by the maintainer (over the Rust `MIT OR Apache-2.0` dual-license
  norm) and materialized in the repository's `LICENSE` file.

## Release notes
- **A stable `vMAJOR.MINOR.PATCH` tag push is the publication boundary.**
  `.github/workflows/publish-crates.yml` runs `cargo publish` with the repository's
  `CARGO_REGISTRY_TOKEN`; its manual dispatch is dry-run-only. cargo-dist's generated workflow
  creates the GitHub Release via `GITHUB_TOKEN` and pushes the Homebrew formula using
  `HOMEBREW_TAP_TOKEN`, which needs write access to `jarimustonen/homebrew-glasspad`. The
  release host runs gates and pushes the tag, but publishes none of these channels locally.
  A prerelease `vMAJOR.MINOR.PATCH-*` tag still publishes the prerelease crate and creates a
  GitHub prerelease, but may skip Homebrew; it is not the three-channel stable-release path.
- **The CI legs are not atomic.** crates.io publishing runs in parallel with cargo-dist, and
  Homebrew publication follows GitHub Release creation. Operators verify all three declared
  targets after a cut. Retry a failed crates.io leg with **Re-run failed jobs** on the original
  tag-push run (manual dispatch cannot publish); never delete and re-push the tag, reuse a
  version, or try to republish one already present on crates.io.
- **crates.io publish is permanent** — a name+version can never be re-published; `cargo yank`
  only hides it. Run `cargo publish --dry-run` as a gate, but never use a local real publish
  path for this repository.
- **Binary coverage is deliberately narrower than source-install coverage.** Prebuilts cover
  `aarch64-apple-darwin`, `aarch64-unknown-linux-gnu`, and
  `x86_64-unknown-linux-gnu`; Intel-mac and Windows users install from crates.io with
  `cargo install glasspad`.
