# Visual language

Glasspad should feel like a precise working surface, not a branded presentation layer. Content is the hero. The visual direction combines warm paper-like light mode, calibrated deep dark mode, native typography, restrained borders, and one interactive accent.

## Character

- Quiet, compact, and deliberate; suitable for data-heavy work and long reading sessions.
- Structure comes from spacing, fine borders, and small background steps rather than decoration.
- Use one accent for links, focus, and current/next action. Do not use it as ornament.
- Avoid gradients, glassmorphism, heavy shadows, oversized display type, and decorative icon sets.
- Preserve visible keyboard focus and never rely on color alone for status.

### Status tokens

Each state has solid, soft-fill, and readable-text forms:

- `--gp-status-done`, `--gp-status-done-soft`, `--gp-status-done-text`
- `--gp-status-next`, `--gp-status-next-soft`, `--gp-status-next-text`
- `--gp-status-blocked`, `--gp-status-blocked-soft`, `--gp-status-blocked-text`
- `--gp-status-future`, `--gp-status-future-soft`, `--gp-status-future-text`

Status labels must also say “Done”, “Next”, “Blocked”, or equivalent. Color alone is insufficient.

### Type and reading tokens

| Token | Meaning |
|---|---|
| `--gp-font-sans` | System UI stack for dashboards and data |
| `--gp-font-mono` | System-oriented monospace stack for code and technical values |
| `--gp-font-serif` | System serif stack for long-form reading |

| `--gp-prose-font-size` | Long-form body size, currently about 18 px |
| `--gp-prose-line-height` | Long-form line height, currently 1.75 |

The exact shipped token declarations are included in [`base.css`](base.css).

## Existing component vocabulary

Use existing classes where their semantics fit; adding a template-local class is fine when it is documented.

- `.gp-card`: bordered 12 px-radius surface with standard padding and shadow.
- `.gp-stat`, `.gp-stat-value`, `.gp-stat-label`: compact metric tile and hierarchy.
- `.gp-prose`: centered serif reading column. Its inserted Markdown blocks must be direct children.
- `.gp-chart` or `[data-gp-chart]`: responsive chart mount region.
- `.gp-doc`, `.gp-toc`, `.gp-toc-*`: current optional long-form table-of-contents rail generated by Glasspad.
- `.gp-diagram`, `.gp-node`, `.gp-node-label`, `.gp-edge`, `.gp-edge-arrow`: authored inline-SVG diagram structure.
- `.gp-status-*`, `.gp-legend`, `.gp-chip`: semantic status coloring and legend.
- `.gp-muted`: muted supporting text.

## Composition conventions

- **Spacing:** work from an 8 px rhythm: 4, 8, 12, 16, 24, and 32 px equivalents. Cards normally use 24 px internal padding and 24 px gaps.
- **Radius:** 4 px inline details, 8 px tiles/items, 12 px primary sections, pill only for compact tags.
- **Depth:** one fine border plus `--gp-shadow` at most. In dark mode, surface luminance does most of the work.
- **Typography:** use 400 for reading, 600 for labels/emphasis, 700 for titles and primary metrics. Dashboard section labels may be compact uppercase; prose headings remain sentence case.
- **Data:** prefer compact rows and stable alignment. Monospace is useful for code and technical identifiers, not automatically for every number.
- **Interaction:** links remain recognizable; focus uses a 2 px `--gp-focus` outline with offset. Hover cannot be the only cue.

## Responsive and theme behavior

At narrow widths, grids become one column, page padding reduces, optional side rails disappear, and local overflow regions keep wide content contained. A practical current breakpoint is 48 rem for card grids and 60 rem for the prose TOC rail; choose based on content rather than device names.

The host sets `data-theme="light"`, `data-theme="dark"`, or `data-theme="auto"` on the document root. Templates should respond through tokens without selectors that assume the host's outer shell. Check both explicit themes and system-driven auto mode.
