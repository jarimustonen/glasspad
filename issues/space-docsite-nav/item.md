# Grouped/nested space nav + generated landing index (port a structured docsite off build_docs.py)

## Description

**Motivation (found 2026-08-13, from `../aggountant` `issues/design-v2/`).** aggountant maintains
its living design spec as a docsite generated by a bespoke `issues/design-v2/tools/build_docs.py`
(2800+ lines, Python stdlib), and reads it via `tw view issues/design-v2/index.html`. The stated
goal for a year has been to **retire build_docs.py and feed glasspad the markdown** (aggountant
issues `docsite-to-glasspad`, `docsite-glasspad-maalla-hosted`). glasspad 0.6/0.7 got most of the
way — markdown-native spaces, multi-page publish, bridge nav — but the docsite still can't fully
port. This issue captures the **structural glasspad gaps** that keep build_docs.py + `tw view`
alive, verified empirically against glasspad 0.7.0.

### Why `tw view` is still needed (two separate reasons)
1. **Loopback-only viewing** — `glasspad serve`/loopback binds `127.0.0.1`, only viewable on the
   host machine; Jari's seat browser is elsewhere, so `tw view` bridges server→seat. **0.7.0
   publish-first + hosted `target` removes this** — `glasspad publish issues/design-v2` → a hosted
   URL viewable anywhere — **once `glasspad.maalla.dev` is upgraded** (blocked in aggountant
   `docsite-glasspad-maalla-hosted`; an **ops** redeploy, NOT a glasspad code gap).
2. **The index/nav structure doesn't port** — even served/published, glasspad's space model is
   structurally flatter than build_docs.py's index. **This issue is that gap.**

### Empirical findings (glasspad 0.7.0, on `design-v2`)
- **Flat nav only.** `src/artifact_host/space.rs`: `nav` is a single-level ordered slug list
  (manifest `nav:` order, else lexicographic). No groups, no nesting. build_docs.py renders a
  **grouped** sidebar (Spec / *ADR:t (johdetut)* / *Suunnitteludokumentit* / Stints) with
  **companions nested** under their parent doc.
- **No generated landing/index.** With no `index.md`, `glasspad build` emits a **redirect stub**
  to the first page (`<meta http-equiv=refresh … url=adr-1-store.html>`), not a curated landing.
  build_docs.py generates a rich `index.html` via `build_index()`/`INDEX_GROUPS` — grouped doc
  cards with per-doc **descriptions/kickers** (e.g. an ADR's `## Decision` statement).
- **Companion-stem slugs rejected.** `glasspad build ../aggountant/issues/design-v2` fails:
  `invalid slug "backtest-architecture-analysis.arkkitehdille"` — dotted companion stems
  (`*.arkkitehdille.md` / `*.kirjanpitajalle.md`) are not valid slugs. The docsite's
  companion-pairing convention can't feed glasspad directly.

## Scope — glasspad's job (this issue)
Design-first. Extend the **space model + structure-only manifest** (`src/artifact_host/space.rs`,
the manifest schema, the bridge nav shell `bridge.js`, and the serve/build/publish render seam) so
a structured docsite ports without a bespoke index generator:

1. **Grouped, one-level-nestable nav** declared in the space manifest (structure-only, still no
   content): named nav groups with ordered members, and a child/parent (companion) nesting under a
   member. Falls back to today's flat lexicographic nav when the manifest declares no groups.
2. **Optional generated landing/index** for a space with no `index.md`: a home page listing the
   docs grouped as above, each with an optional short description sourced from the manifest (or a
   doc's first heading/paragraph) — instead of the redirect stub. Keep `index`/`home` precedence.
3. **Companion stems** — accept (or normalize) dotted companion stems, OR define a manifest-level
   companion mapping so `x` + `x.arkkitehdille` pair up as parent/child in nav. Pick one; document it.

Keep it **structure-only** — no glasspad-owned content/authoring. The security contract is
untouched (each page stays a null-origin sandboxed iframe; `./test-security.sh` stays green).

## Explicitly OUT of scope (stays a thin aggountant-side preprocessor)
glasspad does **not** own these — aggountant keeps a thin preprocessor for them (per
`docsite-glasspad-maalla-hosted`): glossary auto-linking, cross-document section-reference
autolink, section-level TOC, companion **discovery** (the file-naming convention itself), and the
bespoke inline-SVG flow diagrams (`diagrams.py`). This issue only makes the **navigation +
landing structure** first-class so those preprocessor outputs slot into a real glasspad space.

## Done criteria
- A manifest can declare grouped + one-level-nested nav; a space renders that grouped sidebar in
  `serve`/hosted (and degrades gracefully in static `build`, which has no nav shell).
- A space with no `index.md` gets a generated grouped landing page (not a redirect stub).
- A design-v2-shaped dir (grouped spec/ADRs/stints + arkkitehdille/kirjanpitajalle companions)
  publishes/serves with its structure intact, driven only by a manifest + slug-safe md — no
  build_docs.py index/sidebar.
- `/llm-review` before merge; `./test-security.sh` (48 + Wave 2a) green (should be untouched).

## Design decisions (implemented 2026-08-13)

### 1. Grouped, one-level-nestable nav — manifest `groups:`
`glasspad.yaml` gains an optional `groups:` list. Each group has a `label` and
ordered `members`; a member is either a bare slug string or a map with an optional
`title` (display override), `desc` (landing kicker), and one level of `children`:

```yaml
title: aggountant · design v2
groups:
  - label: Perusarkkitehtuuri
    members: [intent, candidate]
  - label: Suunnitteludokumentit
    members:
      - slug: backtest
        title: Backtest-analyysi
        children: [backtest-arkkitehdille, backtest-kirjanpitajalle]
```

`Space.nav_groups` holds the reconciled structure (dangling slugs dropped, dedup,
grandchildren discarded, empty groups dropped, labels/titles/descs sanitized like a
resolved title). **The flat `Space.nav` stays the complete slug allowlist** — groups
are *display curation only*, so an ungrouped page is still reachable, just not listed.
**No `groups:` → empty `nav_groups` → the flat lexicographic nav is byte-compatible**
(the shell renders the existing horizontal bar; the sidebar `<aside>` stays empty and
CSS-hidden). The shell renders a grouped vertical sidebar via `render_with_groups`
(client `createElement` + `textContent`, reusing the one validated `navigateTo`
allowlist path — the security-critical nav model is unchanged).

### 2. Generated landing/index
When a space has **no `index`/`home` page** AND (it declares groups OR has ≥2 pages),
`finalize` synthesizes an `index` artifact — a `gp-prose` fragment listing the docs
grouped (or flat), each with a description (manifest `desc:` → the doc's first
paragraph → none) — and makes it the home. This replaces the old first-artifact
**redirect stub**. Because it is a normal artifact it flows through serve, static
`build` (emitted as `index.html`, no redirect), and hosted publish for free; it is
idempotent (a stored/regenerated space already has `index`, so it is never doubled).
A **single** ungrouped page keeps the old redirect/frame-it behavior (a one-link
landing is worse UX). Existing `index`/`home` precedence is untouched.

### 3. Companion stems — **manifest-level mapping (the chosen approach)**
glasspad does **NOT** accept or normalize the dotted `x.arkkitehdille.md` stems — they
stay slug-invalid (the dot is not in the slug grammar), and the file-naming
*convention* remains the producer's thin preprocessor (explicitly out of scope). The
producer ships **slug-safe** pages (`backtest`, `backtest-arkkitehdille`) and declares
the parent/child relationship via a group member's `children:` mapping. This keeps
glasspad structure-only, respects the OUT-of-scope boundary (companion *discovery*
stays producer-side), and avoids the collision ambiguity that normalizing
`x.arkkitehdille` → `x-arkkitehdille` would create. The nesting is enforced to **one
level** (a child carries no further children).

### Security contract — untouched
Each page stays a null-origin sandboxed iframe; `./test-security.sh` (48 + Wave 2a)
stays green with no edits. The grouped sidebar reuses the exact `navigateTo` grammar +
`KNOWN_SET` allowlist; labels/titles are inserted as `textContent` (never an HTML
sink) and JSON-for-script encoded in the `GROUPS` data literal; the generated landing
HTML-escapes every producer/artifact-derived string. Wire/store carry `nav_groups`
with `#[serde(default)]` (backward-compatible) and re-reconcile on the untrusted
ingest boundary.
