# Architecture

This document is a map of the codebase for contributors: where the major pieces live and
which boundaries matter. For *why* individual decisions were made, see the issue records
under `issues/` (closed issues keep their plans and analyses); for the visual design
system, see [DESIGN.md](DESIGN.md); for agent-facing operational detail, see
[AGENTS.md](AGENTS.md).

## Bird's-eye view

glasspad is an **HTML-artifact host**: a producer (typically an AI agent) authors plain
HTML or markdown files in a directory, and `glasspad serve` hosts each file as a page in
a **null-origin sandboxed iframe**, either on loopback or through a hosted share server.
There is no content DSL and no server-side application framework — the directory of
artifacts is the single source of truth.

The two boundaries a new contributor must understand:

1. **The security boundary is the sandbox, not trust in content.** Every artifact is
   assumed hostile. The host's job is to render it so that it cannot escape its iframe,
   reach another space, exfiltrate data (`connect-src 'none'`), or touch the filesystem.
   `./test-security.sh` (a Playwright suite under `tests/security/`) is the regression
   gate for this promise and must stay green after any change to headers, CSP, the
   shell, or the bridge.
2. **The library/binary boundary is a purity boundary.** The repository publishes **one
   crate (`glasspad`) with two crate roots**: `crates/glasspad-core` is the library
   (pure — no clap, no filesystem, no network, no wall clock; time enters through the
   injected `Clock` trait) and `crates/glasspad-cli` is the binary that owns all I/O.
   This is deliberately *not* two published crates: `Cargo.toml` points `[lib]` and
   `[[bin]]` at the two roots so `cargo publish` and `cargo install glasspad` stay
   single-package operations.

### `crates/glasspad-core/` — pure domain library

- **`artifact_host/`** — the host's deterministic decisions: markdown/fragment rendering
  (`render.rs`), sanitization (`sanitize.rs`), the themed page shell and templates
  (`shell.rs`, `wrap.rs`), and the security-header/CSP policy (`headers.rs`).
- **`data/`** — the legacy data parsers (CSV/JSON/mbox) behind `glasspad data`, with
  type inference and input limits.
- **`security/`** — token generation and related security primitives.
- **`time.rs`** — the `Clock` trait; the only way domain code observes time.

### `crates/glasspad-cli/` — the `glasspad` binary (all I/O)

- **`cli/`** — one module per command group (serve, publish, author, data, skill,
  config, host-serve, submissions, info/doctor); `cli.rs` + `help.rs` own the clap
  surface and the machine-readable `--help --json` tree.
- **`artifact_host/`** — the HTTP/filesystem side of the host: routes and response
  assembly, header application, space scanning (`space.rs`), path guards
  (`guards.rs`), and the served base assets under `assets/` (`base.css`, `charts.js`,
  `bridge.js`, `manifest.json`, exposed at `/_gp/v1/`). Has its own `AGENTS.md`.
- **`hosted/`** — the hosted share server: auth, slug allocation, ingest/storage of
  published spaces, and response submission handling (`submit.rs`, `rounds.rs`).
- **`server.rs`, `config.rs`, `pidfile.rs`, `clock.rs`** — the axum server harness,
  config resolution, process management for `serve`, and the wall-clock `Clock`
  implementation injected into the core.

### Top level

- **`tests/`** — CLI-level integration tests (one file per command surface) plus
  `tests/security/`, the Playwright adversarial suite driven by `./test-security.sh`.
- **`build.rs`** — stamps the git commit into the binary for `glasspad version`.
- **`examples/`** — example artifact spaces.
- **`.github/workflows/`** — `ci.yml` (contribution gate) and the tag-triggered release
  workflows (`publish-crates.yml` for crates.io, cargo-dist's `release.yml` for GitHub
  Releases + Homebrew).

## Cross-cutting concerns

**Security model.** Artifacts render inside a null-origin (`sandbox` without
`allow-same-origin`) iframe with a strict CSP; same-space navigation and theming go
through the injected `bridge.js` rather than any shared origin. Changes anywhere along
the request path — headers, shell wrapping, asset serving, hosted publishing — are
security-relevant and gated by `./test-security.sh`.

**Purity and injected time.** `glasspad-core` must stay free of `std::fs`, network, and
`SystemTime::now()`; effects enter through parameters and the `Clock` trait. Verify by
grep when touching core, not by inspection.

**AI-first CLI surface.** Every command follows the family CLI canon: strict input
validation, `--json` output with `schema_version`ed envelopes, no interactive prompts,
informative errors. `glasspad --help --json`, `version --json`, `doctor`, and
`skill list/print/install` share one source of truth for supported schemas and bundled
skills — a test pins the agreement; do not introduce a second list.

**Configuration.** Behavior (loopback vs. hosted publishing, space templates) is
config-driven: per-space `glasspad.yaml` plus user-level configuration resolved in
`config.rs`; `glasspad config` and `glasspad doctor` expose the effective result.
